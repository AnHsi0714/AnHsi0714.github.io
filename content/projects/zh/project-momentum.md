# 律動計畫 Momentum

## 專案簡介

一個告訴自己「現在該做什麼」的個人時間表網頁。畫面最上方顯示目前的時段、還剩多少時間，以及下一個時段是什麼。每天可以勾選習慣、寫進度筆記，週末回答固定的回顧問題。

時間表是依照自己的作息排的（上課、深度工作、英文、閱讀、運動、就寢），但時段與習慣都放在設定檔裡，換成自己的習慣也能使用。

### 起源與動機

在經歷推甄面試的摧殘後，意識到自己與理想目標之間仍有不少差距，也開始重新思考過去閱讀《原子習慣》時提到的觀念：比起單純依靠意志力，建立適合自己的系統與環境，或許才是維持長期行動的關鍵。

考量到自己較習慣一次投入較長時間完成事情，因此將 Project Momentum 設計成以深度工作為核心的個人時間管理系統。透過預先安排每日任務，建立穩定的工作節奏，同時保留任務與休息時段的調整彈性，讓使用者能依照當天的實際情況進行變動，而不必受限於僵化的時間表。

最終目標不只是提高時間利用率，更希望藉由系統化的安排，逐步培養持續執行、適時休息，以及重新回到工作狀態的能力。

### 設計理念與核心原則

Project Momentum 並非單純的待辦事項清單，而是以時間區塊為基礎，結合任務管理、休息安排與每週回顧的個人時間管理系統。設計上以以下原則為核心：

1. **深度工作（Deep Work）**：以較長的時間區塊安排任務，減少頻繁切換造成的干擾，讓使用者能夠專注投入單一活動，而非不斷在不同任務之間切換。
2. **彈性調整（Flexibility）**：預先規劃每日時間表，但不將其視為不可變動的限制。遇到臨時任務或突發狀況時，允許使用者調整當日任務的時間與順序，在維持整體規劃的同時保留彈性。
3. **主動執行（Active Execution）**：任務的開始與結束由使用者主動操作，而非單純依照預定時間自動判定。藉由實際操作記錄任務執行情況，讓規劃時間與實際投入時間有所區別。
4. **適當恢復（Recovery）**：將休息視為時間管理的一部分，而非工作之間的空白。除了娛樂性休息，也考慮短暫睡眠與恢復體力的需求，避免長時間工作或低品質休息影響後續執行。
5. **持續改善（Continuous Improvement）**：透過每週回顧檢視任務完成情況、時間分配與執行上的困難，逐步調整後續安排，而非只追求單次計畫的完成率。

## 設計取捨與使用心得

Project Momentum 是從個人實際需求出發的專案，因此部分設計並非單純追求操作便利，而是考量使用者的行為習慣，以及不同機制可能造成的影響。

1. **不自動延續未完成任務**
   - **設計方式**：當日未完成的任務不會自動移至隔天，若要在其他日期執行，必須重新安排。
   - **設計考量**：避免未完成任務持續累積，導致後續時間表越來越擁擠，也讓使用者能重新評估任務的優先順序。
2. **保留當日時間調整彈性**
   - **設計方式**：任務可以在同一天內調整時間；若有新的任務需要安排，則透過插入機制調整既有時間表。
   - **設計考量**：相較於完全固定的時間表，希望在保留原有規劃的前提下，讓使用者能因應當天的實際情況進行調整，而不是因為一項臨時任務就放棄整份安排。
3. **透過開始與結束操作記錄實際時間**
   - **設計方式**：任務需要由使用者手動開始與結束。若前一項任務尚未結束，經過的時間仍計入該任務；結束後至下一項任務開始前，則視為休息時間。
   - **設計考量**：不直接將預定時間視為實際執行時間，希望藉此觀察計畫與實際行為之間的差異。
4. **區分娛樂與恢復型休息**
   - **設計方式**：除了一般休息時段，也允許使用者額外插入恢復休息，例如短暫睡眠或閉眼放鬆。
   - **設計考量**：實際使用時發現，休息不一定等於恢復體力。例如滑手機雖然能帶來娛樂，卻不一定能改善疲勞。因此希望讓休息安排更符合實際需求，而不是單純延長休息時間。
5. **不以懲罰作為主要管理方式**
   - **設計方式**：保留任務延後、取消與未完成等紀錄，透過每週回顧檢視執行情況，而非單純以扣分或懲罰要求使用者完成任務。
   - **設計考量**：單純累積失敗紀錄或懲罰，可能使使用者逐漸對紀錄失去感受。因此希望透過回顧找出反覆發生的問題，進一步調整系統與執行方式。

## 技術架構

- **前端**：Vite + TypeScript，畫面用 lit-html 渲染並拆成元件，樣式使用 Sass。
- **設定**：時間表、習慣與每週目標、名詞解釋分別放在 `src/config/` 下的設定檔。
- **資料**：只存在自己的電腦。以 `npm run dev` 執行時寫入專案內的 `data/momentum.json`，瀏覽器也保留一份；`data/` 不進版本控制，備份透過回顧頁匯出。
- **無障礙**：新增畫面都要符合 WCAG AA，build 前會先跑型別檢查與對比度、字級檢查。

## 目前進度

四個畫面的核心功能已完成，包含任務開始與結束的時間記錄、浮動項目、自由拖曳調整時間表與衝突清單，以及從紀錄判斷習慣是否完成。

## 未來工作

- **時間表**：檢視平日與週末各時段的安排是否過滿或過鬆，決定幾段空檔的用途。
- **自主專案**：選定主題（最多兩個並行）、分配深度工作時段、訂出階段與第一個里程碑，並在資料中加入專案紀錄。
- **運動**：訂出各天的訓練內容與進度追蹤方式。
- **客製化**：讓使用者能自訂任務項目類型與內容。
- **回顧**：選定衡量進度的指標，並顯示在回顧頁。
- **資料成長**：資料檔超過 2–3 MB 時先壓縮 JSON，再按年份封存。
