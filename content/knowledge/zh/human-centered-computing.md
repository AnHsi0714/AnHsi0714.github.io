## HCC 從哪裡來

Human-Centered Computing（人本計算，HCC）不是一個獨立的研究方法，而是一種「先問人，再問系統」的立場。它常被拿來跟 <span data-term="human-computer-interaction">Human-Computer Interaction（HCI）</span>放在一起講，但兩者的關係比較像是「共同的核心價值」跟「其中一支具體研究領域」：HCC 是出發點，HCI、<span data-term="social-computing">Social Computing</span>、User-Centered Design 這些領域，都可以看作是這個立場在不同情境下的具體實踐。

## 跟 HCI 的差別

單看 HCI，研究對象通常聚焦在「人跟電腦系統之間的互動」本身：介面好不好用、操作流程順不順。但 HCC 問的問題更早一步：這個系統存在的理由是什麼，它服務的是誰的需求、誰的價值觀。如果只優化「好不好用」，卻沒有先確認做的東西真的對人有意義，那就只是把一個不必要的系統做得很順手而已。

## CodePulse 裡的具體例子

CodePulse 這個專案本身橫跨了好幾種研究方法，把它們攤開來看，會發現底層其實都在回答同一組 HCC 式的問題。

| CodePulse 的作法 | 對應的 HCC 關聯 |
| --- | --- |
| 前端互動設計 | 以人的需求與使用方式設計系統 |
| 使用者研究 | 直接研究人與系統的互動 |
| A/B crossover study | 以使用者資料評估系統設計 |
| 前後測 | 觀察系統對學習者的影響 |
| 問卷、自陳信心 | 研究使用者的主觀感受 |
| 發現 information overload | 根據人的認知與行為調整系統 |
| Data Structures Visualization | 讓系統配合人的理解與學習 |

這些工作各自落在人機互動、資訊視覺化的方法論裡，不是各自獨立的技能清單。把它們放在一起看才會發現，每一項選擇背後其實都是同一個判斷標準：這樣設計對「人」有沒有幫助，而不是這個功能技術上做不做得到。

## 為什麼這對我重要

我一開始理解 CodePulse 的方式，是把它拆成一堆技術任務：做視覺化動畫、跑使用者測試、算統計顯著性。直到後來重新回頭梳理這些工作彼此的關係，才發現它們背後其實共用同一個立場，也就是 HCC。這也是我想在研究所深入<span data-term="information-visualization">資訊視覺化</span>、人機互動方向的原因：比起單純把系統做出來，我更想學會怎麼有系統地驗證「這個系統對人真的有幫助」，而不是只憑直覺判斷好不好用。
