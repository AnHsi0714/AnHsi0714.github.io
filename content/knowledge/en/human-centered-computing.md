## Where HCC comes from

Human-Centered Computing (HCC) isn't a standalone research method. It's a stance: ask about people first, then ask about the system. It's often mentioned in the same breath as <span data-term="human-computer-interaction">Human-Computer Interaction (HCI)</span>, but the relationship between the two is closer to "shared core value" versus "one concrete field built on it": HCC is the starting point, and fields like HCI, <span data-term="social-computing">Social Computing</span>, and User-Centered Design can each be read as that stance put into practice in a different context.

## How it differs from HCI

HCI on its own tends to focus on the interaction between a person and a computer system itself: is the interface usable, does the workflow feel smooth. HCC asks an earlier question: why does this system need to exist at all, and whose needs and values is it actually serving? If you only optimize for "is it usable" without first confirming the thing is worth building, you've just made an unnecessary system pleasant to use.

## A concrete example from CodePulse

CodePulse spans several different research methods on its own. Laid out side by side, they turn out to be answering the same set of HCC-shaped questions underneath.

| What CodePulse did | HCC connection |
| --- | --- |
| Frontend interaction design | Designing the system around human needs and usage patterns |
| User research | Directly studying human-system interaction |
| A/B crossover study | Evaluating system design with user data |
| Pre/post testing | Observing the system's effect on learners |
| Surveys, self-reported confidence | Studying users' subjective experience |
| Discovering information overload | Adjusting the system based on human cognition and behavior |
| Data structures visualization | Fitting the system to how people understand and learn |

Each of these already sits inside HCI or information-visualization methods; they're not a random list of unrelated skills. Lay them side by side and one judgment call keeps showing up underneath every one of them: does this design actually help a person, rather than whether the feature is technically achievable.

## Why this matters to me

I originally understood CodePulse as a pile of separate technical tasks: build the visualization animations, run the user study, compute statistical significance. It wasn't until I went back and traced how those pieces of work relate to each other that I noticed they all share the same underlying stance, which is HCC. That's also why I want to go deeper into <span data-term="information-visualization">information visualization</span> and HCI in graduate school: more than just building a system, I want to learn how to systematically verify that a system actually helps people, instead of judging "is it good" by gut feeling alone.
