文章、知識點、專案、小作品四個詳情頁在內容不存在時，原本是 EmptyState 在上、「回列表」連結在下，且連結靠左、EmptyState 置中，看起來順序顛倒。四頁都改成連結在上（`mb-4`）、EmptyState 在下，和一般詳情頁返回連結在上方的位置一致。

### 新增全站 404 頁

`/projects/1/1` 這種多一層的路徑沒有任何路由匹配，router 又沒有 catch-all 也沒設 `errorElement`，所以會顯示 React Router 內建的英文錯誤頁，沒有導覽列和樣式。

- 新增 [NotFound.tsx](../../../src/pages/NotFound.tsx)，版面與詳情頁的找不到狀態一致（回首頁連結在上，下方 EmptyState）。[router.tsx](../../../src/router.tsx) 最後加 `path: '*'`，字串放在 `common.pageNotFoundTitle` 與 `pageNotFoundDesc`（[strings.ts](../../../src/i18n/strings.ts) 中英都有）。
- [prerender.ts](../../../scripts/prerender.ts) 在寫入首頁快照前，把還沒被覆蓋的 `dist/index.html` 複製成 `dist/404.html`。GitHub Pages 遇到沒預先產生的路徑會回 `404.html`，沒有這份的話，直接輸入壞網址會看到 GitHub 自己的 404 頁，app 根本不會載入，catch-all 也就接不上。
- 兩者分工：catch-all 管 app 載入後顯示什麼，`404.html` 管 app 能不能載入。本機 dev server 與 `vite preview` 都會把未知路徑導回 `index.html`，所以 `404.html` 的實際效果只能部署後確認，尚未驗證。

### 補裝 @types/node

`prerender.ts` 用到 `node:fs`、`node:path`、`node:url`、`process`，但專案沒裝 `@types/node`，IDE 開這個檔案會有 4 個紅線。`tsx` 執行不檢查型別、`npm run build` 的 `tsc --noEmit` 只檢查 `src`，所以建置不受影響，只是 IDE 顯示錯誤。已 `npm i -D @types/node`。
