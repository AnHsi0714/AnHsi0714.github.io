### 新增作品「星座碎片」sketch 移植

原稿「Celestial Fragments」用 `windowWidth`／`windowHeight` 畫滿整個瀏覽器視窗，靠 `windowResized()` 在視窗改變大小時重新 `generate()`；改寫成 instance mode 的 [celestialfragments.ts](../../../src/pages/gallery/sketches/celestialfragments.ts) 時，容器大小固定由外部傳入的 `width`／`height` 決定，不需要監聽 resize。多邊形的位置、半徑本來就是用 `width`／`height` 的比例算出來的，天生會跟著容器等比例縮放，只有描邊粗細、頂點圓點直徑、頂點漂移速度是原稿針對「視窗寬度 ~1912px」寫死的絕對像素值，統一乘上 `k = width / REFERENCE_WIDTH` 縮放。原稿只有 R 鍵手動重製，比照專案其他作品加上點擊畫布重製。

p5 的 `SCREEN`／`ADD`／`MULTIPLY` 混合模式常數在型別上是字串字面量（`p5.BLEND_MODE`），不是數字，`polygons` 陣列裡 `Polygon.mode` 欄位跟著改成 `p5.BLEND_MODE` 型別，`tsc --noEmit` 才過。

[index.ts](../../../src/pages/gallery/sketches/index.ts) 新增 `CELESTIAL_FRAGMENTS_ASPECT`（1912/897，跟現有 `WIDESCREEN_ASPECT` 1872/906 的截圖尺寸不同，另外訂常數）並註冊 `Celestial_Fragments` 這筆 sketch entry。`content/artworks.json` 裡這筆資料（標題「星座碎片」、`openProcessingUrl`、中文描述）已經先補好，這次另外補上 `content/artworks.en.json` 缺漏的英文條目（標題、描述皆為中文版翻譯）。

### 展牆進場填滿、往回捲夾值下限修正

[GalleryGrid.module.scss](../../../src/pages/gallery/GalleryGrid.module.scss) 的 `.wallRow[data-row="1"/"2"]` 用 `margin-left`（15%／7%）做磚牆式錯位排列，但單靠 CSS margin 會讓這兩列進場時左側露出一截空牆，要等自動橫移把 margin「走」完才會填滿。[useWallAutoScroll.ts](../../../src/pages/gallery/useWallAutoScroll.ts) 新增 `resetStagger`：在初始化跟每次真的需要重新分配作品時，直接把這兩列的位移量預先推進到等同 margin 的距離，讓填滿的錯位效果從第一幀就成立，不需要播放「走過去」的過程。滾輪往回捲的夾值下限也從寫死的 `0` 改成每列各自的錯位起點（`staggerOffsetsRef`），避免使用者手動捲回起點時又露出那截空牆。

### 修正切換語言時展牆重新洗牌、隨機換圖

中英文用兩份完全獨立的 JSON（`useLocalized` 直接切換物件參照），切換語言時 `artworks` 陣列連同裡面每個 artwork 物件都換成新參照，即使 slug 順序完全沒變。`useWallAutoScroll.ts` 原本只要偵測到 `artworks` 參照變了就整個重新分配版位（`distributeInitialRows`），而重新分配時每個作品的截圖是重新隨機挑一張，所以切語言就等於換圖。改成比對「作品 slug 序列」而不是物件參照本身：slug 順序沒變（多半是純切換語言）只用新增的 `remapArtworks` 把每個 slot 的 `artwork` 換成新語言版本，版位跟目前顯示的截圖都保持原樣；只有 slug 集合或順序真的變了（換了篩選條件、排序方式）才會真正重新洗牌版位、重挑隨機截圖。

### 新增作品「四角交織」sketch 移植

新增 [cornerconvergence.ts](../../../src/pages/gallery/sketches/cornerconvergence.ts)：原稿吃固定 910x910 正方形畫布，從四個角落各自往相鄰邊延伸線條。`space`（節點間距）跟 `lineWeight` 都是針對「910px 見方」寫死的絕對像素值，統一乘上 `k = size / REFERENCE_SIZE` 縮放。四個角落的畫線邏輯完全相同、只差起點跟終點公式，改寫時合併成一個迴圈跑一組設定陣列，省掉四段幾乎一樣的重複程式碼。

第一版直接照搬原稿 `for(i=0; i<=size; i+=space)` 配合 `countNode` 倒數計數的寫法，靠 910/70 剛好整除成 13 這個巧合讓每個角落畫滿 13 條線；但 `size` 換成外部傳入的容器寬度後不保證整除，浮點數累加也可能跟 `size` 對不上，這個巧合一旦跑掉，`countNode` 又是跨角落共用的倒數計數器，一個角落線條數不對，後面三個角落全部跟著歪掉，畫面比例就跑掉了。改成直接跑固定 13 次（`ORIGINAL_NODE + 1`）迴圈、用 index 算節點位置，不再讓「畫幾條線」取決於 `size` 能不能被 `space` 整除，不需要 `countNode` 那套權宜寫法，四個角落無論容器多寬都固定維持原稿的線條比例。原稿只有 S 鍵存檔，這裡加上點擊畫布重製（換一組新的深淺色背景跟配色）。
